### Additive Home featured-article contract (proposed Cloud migration)

`public_home_featured_article_v1()` returns at most one existing `articles` record DTO: `id`, `slug`, `title`, nullable `summary`, nullable `cover_image_path`, `published_at`, `updated_at`, and `is_featured`. It never returns draft/archived/unpublished rows. If no row is explicitly featured, it returns the most recently published row with `is_featured=false`; an empty table returns no rows. The existing `articles_public_read` RLS remains unchanged. Admin selection is a separate `admin_set_featured_article_v1(article_id, expected_updated_at)` RPC, restricted to `information_manager`/`super_admin`, with atomic single-selection, optimistic concurrency, archive auto-clear, and metadata-only audit. This additive API is documented for Flutter; no Flutter source or runtime was changed/tested. See `docs/runbooks/featured-article-v1.md`.

Public client Web tetap anonim walaupun staf login. Semua transport Flutter dapat memakai JSON/REST yang sama dengan filtering/RLS yang sama; adapter native existing berbasis dart:io hanya mencakup baca artikel/panduan. Runtime UI Flutter dan konsumsi kontak/kejadian/lokasi/laporan mobile tidak dapat dibuktikan dari adapter itu saja. CAPTCHA native memerlukan integrasi mobile yang sah dengan hostname/action yang diizinkan; konfigurasi localhost Web bukan bukti native CAPTCHA berfungsi. Ini gap penerimaan mobile, bukan alasan mengubah atau menurunkan keamanan Gateway.

Tes lokal existing membandingkan devProjectRef, core articleColumns dan filter publik pada Dart/Web. Tes E mengecek filter semua reader publik dan role routing. GET LIVE publik hanya membuktikan reachability sesuai filter; membuktikan data yang sama pada Flutter memerlukan aplikasi tim mobile dan hasil perangkat, yang tidak tersedia/dijalankan pada paket ini.
