## 1. Article schema and public model

The existing table is `public.articles`; articles are not duplicated for the Home feature. The following columns/types come from the Web schema source and additive featured-article migration:

| Column | PostgreSQL type | Null/default and meaning |
|---|---|---|
| `id` | `uuid` | Primary key; generated by `gen_random_uuid()` |
| `author_id` | `uuid` | Nullable FK to `staff_profiles(user_id)` |
| `title` | `text` | Required |
| `slug` | `text` | Required, unique; public detail key |
| `summary` | `text` | Nullable; public card/featured summary |
| `content` | `text` | Required; article body |
| `cover_image_path` | `text` | Nullable; legacy HTTPS cover or private `article-media/...` storage key |
| `source_url` | `text` | Nullable; editorial source link, not the cover URL |
| `publication_status` | `text` | Required, default `draft`; allowed values `draft`, `published`, `archived` |
| `published_at` | `timestamptz` | Nullable except a published article must have a value |
| `created_at` | `timestamptz` | Required, default `now()` |
| `updated_at` | `timestamptz` | Required, default `now()`; maintained by existing update trigger |
| `is_featured` | `boolean` | Required, default `false`; additive featured package, operator reported postflight PASS |

Public article readers return only `publication_status='published' AND published_at IS NOT NULL`. `draft` and `archived` rows are never returned by the public list/detail queries. The public RLS policy is `articles_public_read` for `anon` and `authenticated` with that predicate. `articles_staff_all` grants authenticated staff access only when `has_staff_role(ARRAY['super_admin','information_manager'])` passes. RLS remains the authority; a client-side flag is not authorization.

Safe public JSON row (illustrative shape, not a real article):

```json
{
  "id": "<article-uuid>",
  "slug": "<published-slug>",
  "title": "<title from Supabase>",
  "summary": null,
  "content": "<published article body>",
  "cover_image_path": null,
  "source_url": null,
  "publication_status": "published",
  "published_at": "<RFC3339 timestamp>",
  "created_at": "<RFC3339 timestamp>",
  "updated_at": "<RFC3339 timestamp>"
}
```

The public list selects a field whitelist; do not select `author_id` for public UI unless a specific approved feature needs it. Never return drafts, staff notes, secrets, or private report fields as article content.

## 2. Public query contract

### `/informasi` list

The Web implementation is `listPublishedArticlePage()` in `src/features/content/contentService.ts`. It selects `id,author_id,title,slug,summary,content,source_url,publication_status,published_at,created_at,updated_at,cover_image_path`, filters published/non-null `published_at`, uses exact count, sorts `published_at DESC, id ASC`, and returns six rows per page. Search is case-insensitive title substring (`ilike`), with LIKE metacharacters escaped in the Web client. The mobile list may choose a different fixed page size, but must use a bounded range and retain the same filters and stable ordering.

```dart
const articleColumns =
    'id,title,slug,summary,content,cover_image_path,source_url,'
    'publication_status,published_at,created_at,updated_at';

Future<List<Map<String, dynamic>>> publishedArticlePage(
  SupabaseClient client, {
  int page = 1,
  int pageSize = 20,
  String? titleSearch,
}) async {
  if (page < 1 || pageSize < 1 || pageSize > 100) {
    throw ArgumentError('Invalid article page');
  }
  final start = (page - 1) * pageSize;
  var query = client
      .from('articles')
      .select(articleColumns)
      .eq('publication_status', 'published')
      .not('published_at', 'is', null);
  final term = titleSearch?.trim();
  if (term != null && term.isNotEmpty) {
    if (term.length > 120) throw ArgumentError('Search is too long');
    // Escape LIKE wildcards if search is intended to be literal.
    final literal = term.replaceAll(RegExp(r'[\\%_]'), r'\\$0');
    query = query.ilike('title', '%$literal%');
  }
  final rows = await query
      .order('published_at', ascending: false)
      .order('id', ascending: true)
      .range(start, start + pageSize - 1);
  return List<Map<String, dynamic>>.from(rows);
}
```

To show a total count, make a separate filtered `.select('id').count(CountOption.exact)` request using the same publication and search predicates; or continue with `hasMore = rows.length == pageSize`. The Web currently returns an exact total. Keep page-size and offset bounds to avoid unbounded reads.

### Article detail

The Web `getPublishedArticle(slug)` selects the same public content fields and filters exact slug plus the published predicate. Flutter should do the same and treat no row as not found; never query by guessed/internal ID for public detail.

```dart
Future<Map<String, dynamic>?> publishedArticleBySlug(
  SupabaseClient client, String slug,
) async {
  final row = await client
      .from('articles')
      .select(articleColumns)
      .eq('slug', slug)
      .eq('publication_status', 'published')
      .not('published_at', 'is', null)
      .maybeSingle();
  return row == null ? null : Map<String, dynamic>.from(row);
}
```

### Admin CMS behavior (reference only)

The Web CMS uses `articles` directly for admin list/create/update/archive under the existing authenticated RLS policy. It pages 20 rows, filters by `publication_status`, searches title, sorts `updated_at DESC`, and uses `updated_at` as optimistic concurrency version on update. Deletion is not the normal archive operation. Mobile public clients must not implement Admin mutations. The separate featured selection RPC is described below.

## 3. Informasi Utama / featured article

Admin chooses the existing published article via CMS action **Jadikan Informasi Utama**. The actual field is `articles.is_featured`; it is not a separate table or duplicate article. The selection mutation is `admin_set_featured_article_v1(p_article_id uuid, p_expected_updated_at timestamptz)`, authenticated-only and role-checked for `super_admin` or `information_manager`. It serializes changes, permits at most one active featured row, rejects draft/archived, and writes audit metadata. When an article is archived/unpublished, a trigger clears `is_featured`.

The public reader is `public_home_featured_article_v1()` (no arguments), which returns at most one existing published row:

```text
id uuid, slug text, title text, summary text nullable,
cover_image_path text nullable, published_at timestamptz,
updated_at timestamptz, is_featured boolean
```

The RPC itself falls back to the newest published article (`is_featured=false`) when none is selected; order is `is_featured DESC, published_at DESC, id ASC`. If there are no published rows, it returns an empty set. If the featured article is archived, it is removed from public results, its feature flag is cleared, and the newest remaining published article is returned. No new article is created.

```dart
Future<Map<String, dynamic>?> homeFeaturedArticle(
  SupabaseClient publicClient,
) async {
  final result = await publicClient.rpc('public_home_featured_article_v1');
  final rows = List<Map<String, dynamic>>.from(result as List);
  return rows.isEmpty ? null : rows.first;
}
```

Example result shape (illustrative only):

```json
[{"id":"<article-uuid>","slug":"<published-slug>","title":"<title>","summary":null,"cover_image_path":null,"published_at":"<RFC3339 timestamp>","updated_at":"<RFC3339 timestamp>","is_featured":true}]
```

This RPC and `is_featured` are **DEPLOYED by operator-reported postflight evidence**. Browser acceptance of choose/replace/cancel/archive/fallback/empty and role denial is not established by deployment alone. Use the existing `slug` to navigate to detail.

## 4. Article cover images

### Current server contract

- Bucket: `article-media`, **private**, PNG-only, 5 MiB limit. Browser clients have no direct anonymous insert/update/delete. `article_media_assets` is a private registry, not a public listing API.
- Current storage key format in `articles.cover_image_path`: `article-media/articles/<article-uuid>/<asset-uuid>.png`. This is a storage path, not a public URL. The CMS accepts JPEG/PNG/WebP, converts to PNG (max 1600 px edge and 16 MP), and the `article-media` Edge Function reprocesses/sanitizes it. SVG is rejected. This upload endpoint is Admin-only; Flutter consuming content must not upload covers through it.
- Public cover resolver: `GET /functions/v1/public-article-cover?slug=<published-slug>`. The Edge Function checks the article is currently published and `published_at` is non-null, verifies the stored object path belongs to that article, then issues a redirect to a 60-second signed Storage URL. Bucket visibility remains private. A missing, unpublished, malformed, or unassociated cover returns 404. The Edge deployment is **operator-confirmed**; redirect/image and unpublished 404 browser acceptance is still pending.
- Legacy HTTPS `cover_image_path` values remain supported as direct HTTPS images only if URL validation passes. Do not display URL credentials or tokenized URLs. Never treat the private path as an HTTP URL.
- Empty path, resolver error, HTTP error, or image decode failure: show a neutral cover placeholder while retaining title/body and a retry action. Do not hide the article or expose the private Storage object.
- Cache cover response briefly; signed URL lifetime is 60 seconds. Refresh through the resolver when stale. Do not log signed URLs or persist them as an article field.

```dart
Uri publicArticleCoverUri(String supabaseUrl, String publishedSlug) => Uri.parse(
  '$supabaseUrl/functions/v1/public-article-cover'
  '?slug=${Uri.encodeQueryComponent(publishedSlug)}',
);

// Example widget use:
// Image.network(uri.toString(), errorBuilder: (_, __, ___) => const CoverPlaceholder())
```

Use the resolver for new private `article-media/...` keys. The Edge Function performs the signed redirect; Flutter should not request an anonymous signed URL for a private path unless the deployed Storage policy is explicitly confirmed to allow that exact reader. A previously issued signed URL can remain usable until its short TTL expires.

## 5. Flutter lifecycle and safe client setup

Initialize `supabase_flutter` using the project URL and **publishable/anon client key supplied through the mobile app's normal configuration**. Never put a database password, service-role key, secret key, report tracking token, or Admin access token in the app source, article model, image URL, or logs. For public UI, use an anonymous client/session so an Admin session does not broaden what the presentation layer can read.

```dart
await Supabase.initialize(
  url: AppConfig.supabaseUrl,
  anonKey: AppConfig.supabasePublishableKey,
);
final publicClient = Supabase.instance.client;
```

Refetch when the app opens, resumes, or the app's existing connectivity observer reports internet restored. Cancel subscriptions/timers on dispose. The sample deliberately avoids adding a new connectivity package dependency; connect `onConnectivityRestored()` to the connectivity service already used by the mobile app.

```dart
class ArticleRefreshLifecycle with WidgetsBindingObserver {
  ArticleRefreshLifecycle(this.refresh);
  final Future<void> Function() refresh;
  bool _disposed = false;

  void start() {
    WidgetsBinding.instance.addObserver(this);
    refresh(); // initial open
  }

  void onConnectivityRestored() {
    if (!_disposed) refresh();
  }

  @override
  void didChangeAppLifecycleState(AppLifecycleState state) {
    if (state == AppLifecycleState.resumed && !_disposed) refresh();
  }

  void dispose() {
    _disposed = true;
    WidgetsBinding.instance.removeObserver(this);
  }
}
```

Debounce concurrent refreshes in the repository/controller and avoid aggressive polling. A failed/offline refresh must preserve the last valid article view with an explicit stale/offline marker; it must not imply that no articles exist. Refetch does not require a full application restart or clear user form drafts.

## 6. RLS and operational limits

1. Public list, detail, and featured reader expose only published rows. The mobile client should still explicitly apply the publication filters for predictable behavior; RLS is the server-side boundary.
2. Do not call `admin_set_featured_article_v1` from public screens. Its server grant is `authenticated`; its body requires `has_staff_role(['super_admin','information_manager'])` and an expected `updated_at` version. Mobile Admin integration requires a separate authorized design and is not part of this read contract.
3. No mobile read may query the private registry or report tables to obtain cover images. Use the `public-article-cover` route.
4. Do not use a service-role key, private Storage key as a URL, or public bucket change to work around image failures.
5. Do not assume a deployment proves runtime availability: record 404/403/redirect/image checks separately and do not log full signed URLs.
